Azure Concepts Reference

A practical guide to Key Vault, Blob Storage, App Service, RBAC, Azure Functions, and Triggers — built for developers learning the Azure CLI.

🔐 Azure Key Vault
What is it? Azure Key Vault is a cloud service that safely stores and tightly controls access to secrets (passwords, connection strings), encryption keys, and certificates. Think of it as a bank vault for your application's sensitive data — only authorised identities can open it, and every access is logged.

Three Things Key Vault Stores

🔑 Secrets

Any string value you want to keep safe: connection strings, API keys, passwords. Retrieved at runtime, never stored in code.

🗝️ Keys

Cryptographic keys (RSA, EC) used for encryption and signing. Azure manages the key material — your app never sees the raw key bytes.

📜 Certificates

TLS/SSL certificates with automated renewal. Key Vault can generate, store, and rotate certificates for your domains.

How Access Works

Access Policies (what we use in this lab)

  • Set directly on the vault resource
  • Only needs Contributor rights
  • Permissions: get set list delete
  • Simpler for restricted environments

Azure RBAC (alternative)

  • Uses subscription-level role assignments
  • Requires User Access Administrator
  • Roles: Secrets Officer, Secrets User
  • More granular, better for enterprise

Key CLI Commands

REM Create a vault
az keyvault create --name %KV_NAME% --resource-group %RG% --location %LOCATION%

REM Grant yourself access (Access Policy)
az keyvault set-policy --name %KV_NAME% --object-id %MY_OID% --secret-permissions get set list delete

REM Store a secret
az keyvault secret set --vault-name %KV_NAME% --name "MySecret" --value "my-value"

REM Read a secret
az keyvault secret show --vault-name %KV_NAME% --name "MySecret" --query value -o tsv
✅ Best Practice Never store secrets in appsettings.json, environment variables, or source code. Put them in Key Vault and let DefaultAzureCredential fetch them at runtime.
📦 Azure Blob Storage
What is it? Blob Storage is Azure's object storage service — designed to store massive amounts of unstructured data: images, videos, documents, logs, backups. "Blob" stands for Binary Large Object. It's cheap, durable (replicated 3–6 times), and accessible from anywhere via HTTPS.

A Storage Account is the top-level namespace (globally unique name). Inside it you create Containers (like folders). Inside containers are Blobs (the actual files).

Blob Types

TypeBest ForNotes
Block BlobFiles, images, videos, backupsWhat you use 95% of the time. Supports parallel upload of large files.
Append BlobLog filesOptimised for append-only writes. Cannot modify existing content.
Page BlobVirtual machine disks (VHD)Random read/write access. Used internally by Azure VMs.

Access Tiers (Cost vs Speed)

CoolLowerHigherData accessed monthly

.NET SDK Pattern

// Connect to storage
var client = new BlobServiceClient(connectionString);

// Get or create a container
var container = client.GetBlobContainerClient("uploads");
await container.CreateIfNotExistsAsync();

// Upload a file
var blob = container.GetBlobClient("logo.png");
await blob.UploadAsync(fileStream, overwrite: true);

// Download a file
var download = await blob.DownloadContentAsync();
byte[] data = download.Value.Content.ToArray();

Key CLI Commands

REM Create a storage account
az storage account create --name %SA_NAME% --resource-group %RG% --sku Standard_LRS --kind StorageV2

REM Create a container
az storage container create --name uploads --account-name %SA_NAME% --auth-mode login

REM Get the connection string
az storage account show-connection-string --name %SA_NAME% --resource-group %RG% -o tsv

REM List blobs in a container
az storage blob list --container-name uploads --account-name %SA_NAME% --auth-mode login -o table
⚠️ Connection String Security A Blob Storage connection string gives full read/write access to everything in the account. Never commit it to source control. Store it in Key Vault and retrieve it at runtime.
🌐 Azure App Service & Deployment
What is it? Azure App Service is a fully managed platform for hosting web applications, REST APIs, and mobile backends. You give it your compiled app and it handles the OS, runtime, patching, scaling, and load balancing. You focus on code, not infrastructure.

Key Components

App Service Plan

Defines the VM size and pricing tier (F1 Free, B1 Basic, S1 Standard…). Multiple apps can share one plan and split the cost.

Web App

The actual hosted application. Has its own hostname (appname.azurewebsites.net), app settings, and deployment slots.

Managed Identity

A passwordless Azure AD identity attached to the app. Use it to access Key Vault, Storage, and other services — no credentials needed.

App Settings

Key-value configuration injected as environment variables at runtime. Safer than hardcoding but less secure than Key Vault for secrets.

Pricing Tiers

StandardS1–S3ProductionAutoscale, 5 deployment slots, custom domains + SSL
PremiumP1v3–P3v3High-traffic productionFaster VMs, VNet integration, 20 slots

Deployment Methods

Zip Deploy (what we use)

  • Pre-compile locally with dotnet publish
  • Zip the publish output
  • Push via az webapp deploy --type zip
  • Fast, predictable, no server build

Other Common Methods

  • GitHub Actions — CI/CD on every push
  • Azure DevOps Pipelines — enterprise CI/CD

  • Docker container — deploy a container image

🛡️ RBAC — Role-Based Access Control
What is it? RBAC is Azure's authorisation system. It controls who can do what on which resources. Instead of granting full admin access to everyone, you assign the smallest role that covers what someone actually needs. Every Azure resource — VMs, Key Vaults, Storage accounts, subscriptions — can have RBAC roles assigned to it.

Three Core Concepts

Security Principal (Who)

The identity being granted access: a User, a Group, a Service Principal (app identity), or a Managed Identity (passwordless app identity).

Role Definition (What)

A named set of permissions. Built-in examples: Owner, Contributor, Reader, Key Vault Secrets User. You can also create custom roles.

Scope (Which Resource)

How broadly the role applies: entire Subscription, a Resource Group, or a specific Resource. Narrower scope = safer.

Scope Hierarchy

Management Group
Widest
→
Subscription
→
Resource Group
→
Resource
Narrowest

Roles assigned at a higher scope are inherited by everything below it. Assigning at the resource level limits blast radius if something goes wrong.

Common Built-in Roles

RoleCan DoCannot Do
OwnerEverything, including grant access to others—
ContributorCreate and manage resourcesGrant roles to others
ReaderView resourcesCreate, modify, or delete anything
User Access AdministratorGrant roles to othersCreate or manage resources
Key Vault Secrets OfficerRead, write, delete secrets in a vaultManage vault settings or keys/certs
Key Vault Secrets UserRead secrets onlyWrite or delete secrets

RBAC vs Key Vault Access Policies

Azure RBAC for Key Vault

  • Requires --enable-rbac-authorization true on vault
  • Needs User Access Administrator or Owner to assign roles
  • Unified with all other Azure RBAC — one place to manage all access
  • Recommended for enterprise environments

Key Vault Access Policies

  • Default mode (no extra flag needed)
  • Only needs Contributor on the vault resource
  • Set with az keyvault set-policy
  • Simpler for labs and restricted subscriptions

Key CLI Commands

REM Check your current role assignments
az role assignment list --assignee (az ad signed-in-user show --query id -o tsv) -o table

REM Assign a role (requires User Access Administrator or Owner)
az role assignment create ^
  --role "Key Vault Secrets User" ^
  --assignee <principal-id> ^
  --scope /subscriptions/<sub-id>/resourceGroups/<rg>/providers/Microsoft.KeyVault/vaults/<vault>

REM Set Key Vault access policy (only needs Contributor)
az keyvault set-policy --name %KV_NAME% --object-id %PRINCIPAL_ID% --secret-permissions get list
💡 Principle of Least Privilege Always grant the narrowest role at the narrowest scope. A running app should get get list on secrets — never set delete. A developer needs more during setup but the deployed app doesn't.

⚠️ Why Can't I Grant Access Even Though I'm "Owner"?

This is one of the most common sources of confusion in Azure labs and enterprise environments. Being called an "owner" in everyday language does not always mean you hold the Azure RBAC Owner role. Here are all the reasons a user can be blocked from granting access:

ReasonWhat's HappeningFix
Contributor, not Owner Contributor is extremely powerful — it can create and manage all resources — but it explicitly cannot perform Microsoft.Authorization/roleAssignments/write. Role assignment is reserved for Owner and User Access Administrator. Grant the user Owner or User Access Administrator scoped to the resource group, or use Key Vault Access Policies instead (only needs Contributor).
Owner at resource level, not subscription/RG level Scope matters. Being Owner of a specific Key Vault lets you manage that vault, but assigning roles at subscription or resource-group scope still requires Owner or User Access Administrator at that level. Check the exact scope of the Owner assignment: az role assignment list --assignee <id> -o table
PIM — role not activated Many enterprise subscriptions use Privileged Identity Management (PIM). The Owner role is assigned "eligible" but must be explicitly activated for a time window before it takes effect. Outside that window, the user has no elevated rights. Activate the role through the Azure Portal → PIM → My Roles → Activate. Wait a few minutes for propagation.
Azure AD / Entra ID vs Azure RBAC are separate Azure RBAC controls access to Azure resources (VMs, Storage, Key Vault…). Azure AD controls directory objects (users, groups, app registrations). A user can be Owner on a subscription but still have no rights to read or create Azure AD objects. This is why az ad signed-in-user show can fail even for subscription Owners. Azure AD operations require separate permissions — at minimum the Directory Readers role in Azure AD, or the Global Administrator grants the operation.
Guest user in the tenant External accounts (e.g. someone invited via B2B) are Guest users in the tenant. Guests have restricted Azure AD permissions by default — they cannot enumerate users, groups, or service principals, even if they hold Owner on a subscription. A tenant Global Administrator must elevate the guest's Azure AD permissions, or convert them to a Member user.
Azure Policy deny assignment An Azure Policy at management group or subscription level can explicitly deny specific operations, overriding even Owner. This is common in enterprise environments with a central platform team managing guardrails. Check az policy assignment list -o table. Contact the platform/cloud team to get an exemption or adjusted policy.
Resource lock A ReadOnly lock on a resource group or subscription blocks all write operations — including role assignments — for everyone except those who can remove the lock (Owner at the lock scope). Check: az lock list --resource-group %RG% -o table. Remove the lock if appropriate.
Subscription type restrictions Free trial, Dev/Test, MSDN, and some sponsored subscriptions have quota and permission restrictions baked in by Microsoft. Certain operations (especially large role assignments or resource creation) are blocked at the platform level regardless of your RBAC role. Upgrade to Pay-As-You-Go, or use Key Vault Access Policies which bypass role-assignment restrictions.
Classic administrator (legacy) Old subscriptions have "Co-Administrator" and "Service Administrator" roles from the pre-RBAC era. These are not the same as modern Owner. A Co-Administrator cannot use az role assignment create — that command only works with the modern RBAC Owner role. Assign the modern Owner RBAC role explicitly via the Portal or CLI.
✅ Quick Diagnostic — Check What You Actually Have Run this to see your exact role assignments and their scopes: 
for /f "delims=" %a in ('az ad signed-in-user show --query id -o tsv') do set MY_OID=%a
az role assignment list --assignee %MY_OID% --all -o table
If you don't see Owner or User Access Administrator at the subscription or resource group scope, you cannot create role assignments — use az keyvault set-policy instead.
⚡ Azure Functions
What is it? Azure Functions is a serverless compute service. You write a small, focused piece of code (a "function") and Azure runs it only when triggered — by an HTTP request, a timer, a new file in Blob Storage, a message in a queue, and more. You pay only for the execution time, and Azure handles all scaling automatically.

Functions vs App Service — When to Use Which

Azure FunctionsApp Service (Web API)
Best forShort, event-driven tasksLong-running request/response APIs
BillingPer execution (first 1M free/month)Always-on VM (hourly)
ScalingAutomatic, to thousands of instancesManual or autoscale rules
StartupCold start possible (first invocation)Always warm
Max runtime10 min (Consumption), unlimited (Premium)Unlimited
StateStateless by designCan hold in-memory state

Hosting Plans

Consumption Plan

Truly serverless. Pay per execution. Scales to zero when idle. Cold starts possible. Best for event-driven, unpredictable workloads.

Flex Consumption (new)

Like Consumption but with faster cold starts, VNet support, and configurable instance size. The modern default.

Premium Plan

Pre-warmed instances (no cold starts), VNet integration, unlimited execution time. Higher cost, enterprise features.

Dedicated (App Service Plan)

Run Functions on a regular App Service plan. Share resources with Web Apps. No cold starts, always-on billing.

Anatomy of a Function

// HTTP Trigger example (C# isolated worker model)
[Function("UploadFile")]
public async Task<HttpResponseData> Run(
    [HttpTrigger(AuthorizationLevel.Anonymous, "post")] HttpRequestData req)
{
    // Your logic here
    var response = req.CreateResponse(HttpStatusCode.OK);
    await response.WriteStringAsync("File processed!");
    return response;
}

// Timer Trigger example — runs every day at midnight UTC
[Function("NightlyCleanup")]
public void Run([TimerTrigger("0 0 0 * * *")] TimerInfo timer)
{
    _logger.LogInformation($"Cleanup ran at: {DateTime.UtcNow}");
    // Archive old blobs, purge expired data, etc.
}

⏰ Triggers & Bindings
What are they? A trigger defines what causes a function to run. Every function has exactly one trigger. Bindings are optional declarative connections to other services (read from a queue, write to a blob) — you declare them as attributes and Azure wires up the connection for you.

Common Triggers

TriggerFires When…Typical Use Case
HTTP An HTTP request arrives REST APIs, webhooks, on-demand processing
Timer A cron schedule fires Nightly cleanup, daily reports, scheduled data sync
Blob Storage A blob is created or modified in a container Image resizing, document processing, virus scanning on upload
Queue Storage A message arrives in a Storage Queue Background job processing, decoupling producers and consumers
Service Bus A message arrives in a Service Bus queue or topic Enterprise messaging, ordered processing, dead-letter handling
Event Grid An Azure event fires (e.g. blob created, VM started) Real-time event reactions across Azure services
Cosmos DB A document is inserted or updated in a Cosmos DB collection Change feed processing, syncing data to search indexes

Timer Trigger — Cron Expression Format

Azure Functions uses a 6-field cron expression: {second} {minute} {hour} {day} {month} {day-of-week}

ExpressionMeaning
0 0 0 * * *Every day at midnight UTC
0 0 9 * * 1-5Weekdays at 9:00 AM UTC
0 */30 * * * *Every 30 minutes
0 0 */6 * * *Every 6 hours
0 0 8 1 * *1st of every month at 8 AM UTC

Bindings Example — Timer + Blob Output

// Trigger: runs every day at midnight
// Output binding: writes a report blob automatically
[Function("DailyReport")]
[BlobOutput("reports/{DateTime}.txt", Connection = "BlobStorageConnectionString")]
public string Run([TimerTrigger("0 0 0 * * *")] TimerInfo timer)
{
    var report = $"Daily report generated at {DateTime.UtcNow}";
    _logger.LogInformation(report);
    return report;  // Azure writes this string to blob storage automatically
}

HTTP Trigger — Authorization Levels

Anonymous

No key required. Anyone with the URL can call the function. Use for public APIs or when you handle auth yourself.

Function

Requires a function-specific API key in the request header or query string. Good for service-to-service calls.

Admin

Requires the master host key. For administrative operations that should never be called by regular clients.
